# 赛题二：演示视频录制脚本

作品名称（建议）：基于安路 PH1P35 的实时图像增强与视觉跟踪系统

适用工程：contest2_hdmi_video，当前交付基线 v89 FPGA＋v83 MCU。
编写日期：2026-10-23。
对照依据：《赛题.pdf》PDF 第16～18页，选题二。

## 一、录制原则与准备

建议成片约6分钟。此时长是制作建议，不是已确认的赛事限制；正式提交前，以报名平台的视频时长、格式、大小及匿名要求为准。若限制3分钟，使用文末精简方案。

拍摄采用两种画面：

- HDMI采集画面：展示真实处理结果，尽量保留完整画面和OSD，不用OBS滤镜美化算法输出。
- 手机实拍：展示开发板、摄像头、按键、数码管、云台和目标，证明实际硬件运行及联动。

素材准备：红色球体；红、绿、蓝简单形状；黑白数字卡（至少0、1、8）；已验证字典的ArUco标记（黑色外框120mm）；中性灰/白色物体；可调台灯。数字和ArUco不要使用尚未验证的新样式。

开拍前检查：

- [ ] 确认提交版本、上电画面和摄像头正常，记录实际固件版本。
- [ ] 确认采集卡没有额外调色、裁切或缩放造成的误差；录制参数尽量设1280×720、60fps，实际支持情况以采集卡为准。
- [ ] 关闭无关弹窗、通知、串口窗口及隐私信息；只录必要画面。
- [ ] 先关闭所有检测显示，KEY2保持云台停止；摄像头对准有纹理、直线和不同颜色的场景。
- [ ] 云台使用已核验的独立供电，检查共地、固定、运动空间及线缆余量；准备随时停止。
- [ ] 各功能先试拍一次。若当前实机不稳定，先修复或明确说明限制，不用成功片段冒充持续稳定。
- [ ] 旁白中的队名、姓名、学校、测量结果按实际填写；匿名评审时删除身份信息。

建议每段多录5秒余量。不同功能段之间可以剪辑，但同一项“开关对比”“跟踪”“启动”尽量连续拍摄；不以加速、抽帧或剪去失败段证明低延迟和稳定性。

## 二、约6分钟分镜与旁白

### 00:00—00:20｜开场与作品定位

画面：作品标题3秒，随后手机拍开发板、摄像头、HDMI屏和双步进云台全景。

操作：暂不开启云台。

旁白：

> 本作品面向赛题二，使用安路PH1P35平台，实现从MIPI摄像头采集、FPGA实时图像处理到HDMI显示的完整链路，并加入目标识别和双轴云台联动，形成一个板内独立运行的视觉系统。

字幕：MIPI采集 → FPGA处理 → 缓存与HDMI输出；板内MCU承担ArUco后处理及运动控制。电脑用于采集录像，不参与实时识别与控制。

### 00:20—00:45｜硬件、启动及架构

画面：硬件近景＋简洁架构图；条件允许时连续拍一次冷启动到摄像头画面出现。

操作：断电重启只能在云台停止、确认安全后进行；启动片段若剪短，注明“启动过程节选”，不要标成启动耗时。

旁白：

> 系统采用SC500摄像头，当前视频链路分辨率为1280乘720。图像增强、基础算法和显示流水线在FPGA端完成，板内MCU处理ArUco相关运算与步进控制。程序固化后可以上电启动，不需要电脑在线计算。

字幕：标注实拍固件版本。仅在本次冷启动实际成功时展示“掉电启动验证”。

### 00:45—01:35｜基础算法与多模式切换

画面：HDMI主画面，角落叠加按键实拍；固定镜头、固定场景。

操作：按KEY1依次切换，每种停留约5～6秒：

| MODE | 画面 | 录制重点 |
| --- | --- | --- |
| 0 | 直通 | 场景原貌、Logo和OSD |
| 1 | 灰度 | 彩色物体变成灰度 |
| 2 | 边缘强度 | 物体轮廓和细线 |
| 3 | 二值化 | 黑白区域分离 |
| 4 | 素描 | 白底轮廓 |
| 5 | 浮雕 | 明暗立体效果 |
| 6 | 卡通化 | 色块量化和轮廓叠加 |

旁白：

> 系统支持七种图像模式，通过按键实时切换，屏幕显示当前模式。灰度、二值化和边缘处理覆盖基础要求，素描、浮雕和卡通化展示风格化扩展。各模式共用视频链路，以控制资源开销。

验收镜头：画面左、右边缘都放置物体；卡通模式用清晰竖边检查描边位置。字幕不要只显示MODE数字，可在后期附上对应算法名称。

### 01:35—02:15｜自动曝光、亮度增益与白平衡

画面：先拍KEY4和数码管，再切HDMI；镜头对准同一组灰白物体和彩色物体。

操作：

1. 保持场景及灯光不动，KEY4关闭→开启，连续记录画面和数码管变化。
2. 功能开启时缓慢降低、恢复照明，保留实际收敛过程。
3. 固定场景，使用台灯改变照明色调，再用KEY3做白平衡关闭→开启对比；等待实际稳定。

旁白：

> KEY4控制自动曝光与亮度增益，数码管固定显示整体增益index和使能状态。改变照明后，可以观察画面亮度的自适应过程。KEY3控制自动白平衡，通过灰白物体观察光源变化下的颜色修正。

字幕：index为控制档位，不是直接的曝光时间或倍数。比较白平衡时固定KEY4状态；比较曝光时固定KEY3状态。若白平衡对比没有可见变化，不配上“明显校正”的旁白，应记录问题并复测。不能宣称恢复已饱和高光的原始细节。

### 02:15—02:45｜颜色、形状与运动检测

画面：HDMI采集＋小窗展示实际物体。

操作：回到MODE0；打开SW1。依次放入不同颜色的简单形状，展示实际出现的框和类别标记；再移动目标、撤走目标，拍运动提示或计数变化。不要把计数说成运动人数。

旁白：

> 系统对简单颜色和形状目标进行检测，在画面中叠加检测结果。同时实现硬件运动检测，通过运动提示或计数反映场景变化。撤走目标后，可以检查检测结果是否及时清除。

注意：颜色及形状名称按屏幕实际结果讲解；需要时后期加图例解释字母，不把错误分类剪成正确分类。

### 02:45—03:30｜红球跟踪与双轴云台联动

画面：手机连续拍到红球、云台和显示器，另外同步保留HDMI采集。建议至少留一段20秒不间断实拍。

操作：确认摄像头安装在云台上；保持颜色检测开启。先放入红球，再按KEY2开启。缓慢左右、上下移动，再做一次较快往返；撤走目标并展示实际响应。最后按KEY2停止，确认已停。

旁白：

> 在目标识别基础上，系统将红球的位置用于双轴步进云台控制。摄像头随云台运动，形成视觉反馈。这里分别展示水平、垂直运动以及目标离开时的实际响应，体现图像处理与外部控制的应用结合。

字幕：标注“KEY2 开/关追踪”。未实测不得说“零延迟”“永不丢失”“无失步”。目标丢失后的策略按实际行为说明，不预先承诺自动搜索或安全停机。

### 03:30—04:10｜ArUco识别与轴线叠加

画面：HDMI，标记始终完整进入画面。

操作：停云台，按需关闭SW1，打开SW2。正对、平移、缓慢旋转和轻度倾斜标记；展示ID、四边形描边及轴线。撤走标记，观察叠加清除。

旁白：

> ArUco功能采用FPGA与板内MCU协同实现，显示标记ID和四边形轮廓，并叠加估计坐标轴。该标记黑色外框边长约120毫米。目前尚未完成实机相机标定，所以轴线用于姿态估计展示，不作为精密位置和距离测量结果。

注意：蓝轴不稳定时不能宣称精确三维位姿。完整保留实际表现，正式成片前决定是否需要进一步修复。

### 04:10—04:40｜数字和两类手势

画面：HDMI；关闭SW2，分项打开对应拨码。

操作：

- 打开SW4，把数字卡放入固定识别框，至少演示0、1、8；卡片不要超出框或严重倾斜。
- 关闭SW4，打开SW3；完整手掌进入视野，张掌、握拳、撤手各保持约3秒。

旁白：

> 数字识别针对固定区域内的数字目标。手势采用纯FPGA两类方案，显示张掌或握拳，撤手后应回到无可靠分类状态。这两项对光照、尺度和背景存在适用条件，目前仍需要针对困难场景继续验证。

字幕：H:O＝张掌，H:F＝握拳，H:-＝无可靠分类。T不是通用手指数量。若本次实拍失败，不能配成功旁白；可以明确列为待改进功能，主展示不依赖它。

### 04:40—05:10｜实时性与资源优化

画面：OSD帧率、D:ms近景；叠加最终综合/布线报告截图，不用综合中间值。

旁白：

> 系统在视频画面中显示帧率和内部延迟统计。当前v89最终布线结果为19450个Slice，占91.68%，使用97块ERAM和32个DSP，最终建立与保持时序检查通过。通过流水线和运算共享，在保留各项功能的同时控制资源占用。

字幕：

- Slice 19450/21216；ERAM 97/108；DSP 32/40。
- Routed SWNS +0.164ns，HWNS +0.020ns，STNS/HTNS＝0。
- D:ms是工程内部统计，不等同于独立测量的摄像头到显示屏端到端延迟。
- OSD所示FPS为内部统计；实际帧率与检测结果刷新率应分开表述。

上述资源数仅适用于已核验v89；若录制前固件变化，替换为对应版本报告，不混用。未完成端到端实测时，不填入推测数值。

### 05:10—05:40｜稳定性和适应性证据

画面：连续运行录像节选，展示真实起止时间、运行时长，以及模式切换和光照变化。

操作：另录连续运行素材。建议先做30分钟基础验收，再根据条件延长；这是工程测试建议，不是赛题规定时长。记录异常次数和当时开启的功能。

旁白模板（完成测量后填写）：

> 在【测试日期】使用【版本】连续运行【时长】，开启【功能组合】，期间进行了【次数】次模式切换和明暗变化，记录到【实际异常情况】。这里展示测试记录和运行片段。

未测则不用此模板，改说：

> 目前已完成模块回归和工程时序检查，长时间板上稳定性仍在验证。本段展示本次连续操作的实际运行情况。

不要用仿真通过、运行计数器或剪接片段单独证明长期无故障。

### 05:40—06:00｜总结

画面：红球跟踪、风格化、识别结果各约3秒，最后回到硬件全景和作品标题。

旁白：

> 本作品完成了MIPI采集、FPGA图像处理、OSD叠加与HDMI实时显示，并围绕图像增强、目标识别和机电联动进行了扩展。系统重点体现板内独立运行、硬件流水线处理和资源受限条件下的功能整合。后续将继续完善复杂光照下的识别稳定性与相机标定。
