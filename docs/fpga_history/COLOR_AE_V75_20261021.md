# v75：先修复曝光反馈，再处理发灰

用户确认前期版本颜色较正常；v74色卡仍发白，KEY4关闭后的截图颜色较浓，但整体较暗。本轮不将这一现象未经验证地归因于v73白平衡优化。版本记录中v72因布局19636 Slice超限未布线，最近一个有成功烧录记录的早期版本是v68；用户无法提供精确正常bit，因此“v72以前正常”作为现象线索而非已确定的固件身份。

## 确认的问题

生产组合中，`ua_luma_stats`的反光容忍模式将每个亮度样本截到72；`design_top_user`的AE设置LUMA_HIGH=72。故中心测光均值永远不大于72，`luma_sync > LUMA_HIGH`常规过亮回调不可达，只剩高光面积分支能降曝光。原来大量回归使用单独构造的均值100等输入，没有检出这项“统计器＋控制器参数组合”缺陷。该问题在v73之前已存在，不能据此声称找到了v73新增回归的唯一原因。

高档提亮还在显示编码之后逐通道加`room/2`，低档加`room/4`，其中room在96..192递减。绿色主通道较亮时不再提升，而较暗红/蓝通道被提升，客观上缩小RGB色差；它不是保持色相/饱和度的线性增益。KEY4关闭会同时改变传感器AE/AG和数字提升，因此截图不能单独区分两者贡献。

## 修改

- 统计模块增加`REFLECTION_CEILING`，历史默认72，产品明确选择96，使测光上限高于AE高阈值72。仍然封顶测光，不恢复对小亮点无限敏感的未截尾均值。
- v74的额外公共补偿曲线在产品关闭；恢复既有基础编码曲线，不叠加未知色度补偿。
- 产品开启`GENTLE_SHADOW_LIFT`，数字提升改为room/16与room/8，主要亮度恢复仍由原传感器自动曝光/模拟增益承担。数字增强未彻底取消，但其造成的通道差压缩明显减轻。
- 白平衡、曝光控制器源码、反光面积阈值、主体下限、所有检测、MCU与电机控制均不改。仍须实机验证，不能声称已恢复特定旧bit的全部硬件效果。
- LUT改动只在既有ROM初始化计算，统计变化为常数阈值；不新增像素拍数、乘法器或RAM bank。最终Slice须≤19518，资源以TD报告为准。

## 新增回归

`tb_meter_v75.sv`将两套真实1280×720统计器并列：144灰场没有原始高光尾计数，但旧封顶结果72，新封顶结果96。控制器对72平台不降曝光，对96能主动降低；暗场仍能回升。暗背景＋约3.125%画面面积的旁侧白反光保持中心24和高光级别0，不因小反光压暗主体。

`test_color_v75.py`独立模型与RTL对照产品参数，包括五组尺寸/位宽、三档强度、帧内强度锁定、脏历史复位、气泡/连续源及完整720p；旧默认回归另行保留。构建只允许三个维护模块相对v73变化，并冻结输入、核验已有未变组件的仿真证据；不冒充当前实景检测已验证。

新增统计＋控制器缺陷复现/修复测试已通过。另行把3.125%白反光移入中央测光区，得到旧均值28、新均值30，高光状态0，均未造成过亮回调压暗主体。五组颜色用例全部通过，包括完整720p三帧、2,764,800有效像素。独立模型核对六个ROM全部12,288字节通过。

为核对v73白平衡优化，将当前模块仅替换投票函数为早期绝对值写法，构造明确标识的`ua_awb_pre73_reconstructed.v`；它不是完整v72源码快照。128×16、64帧、生产9-bit输出及运行开关的逐拍输出、系数和统计对照通过（96,726测试时钟），并不能据此证明厂商映射后或实物硬件绝无问题。当前优先修复已实证的反馈组合缺陷，而非声称已经证实唯一版本回归根因。
