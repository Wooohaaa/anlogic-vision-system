# v54：FPGA＋MCU 掉电保存版

## 范围与授权

用户明确要求“整个完成掉电不丢失，包括 fpga 和 mcu”。本版替换板载 128-Mbit 配置 Flash 启动工程；不写 eFuse、OTP、密钥，不开启舵机。

## 为什么不能仅固化 v53 bit

v53 的 MCU 复位向量为 `0x08000000`，ArUco v39 ELF 由 GDB 加载到易失 TCM。单烧 FPGA bit 不能保证 C 程序掉电保存。本版将 MCU 复位向量配置为 Flash XIP `0x20e00000`，增加 208 字节无栈启动加载器，从 Flash 读取原 v39 二进制、复制到 TCM、核验 CRC32 后跳转原入口 `0x08000100`。

原 MCU ELF SHA256：`D952A80FEE124DDB1B76CCB10783A4C487F13DF9A8B6C9B608504B7992BBF178`，未增加 MCU 手势任务。应用二进制 30296 字节，CRC32 `c7675eda`；加载器不操作任何外设/PWM，头部或 CRC 错误时停机，不跳入损坏应用。

## Flash 布局

| Flash 偏移 | 内容 |
|---|---|
| 0 | 原 v53 布线逻辑，MCU 复位向量配置变体 |
| `0xE00000` | 启动加载器 |
| `0xE10000` | 32 字节头部＋原 v39 应用 binary |

地址窗口以厂商 SDK `gcc_ph1p35_ilm_dlm.ld` 中 Flash `0x20e00000` 为依据；实际板上只读确认 `0x20000000` 可读旧 FPGA 位流，`0x20e00000` 原为全 FF。

## 构建和验证

- FPGA 使用 TD 官方 `update_instance_attribute`，只改一个 `MCU_RESET_VECTOR` 配置属性；比对整个 MCU 属性字符串，其他属性必须完全一致。基于冻结的 v53 Routed DB，不重新综合/移动/布线，不关闭功能。
- 再跑 final timing：SWNS +0.233 ns、HWNS +0.020 ns、STNS/HTNS 0；资源 19494/21216 Slice（91.88%）、97/108 ERAM、25/40 DSP。
- 机器指令级 RV32 单元测试：正常装载进入原入口；magic、空长度、越界长度、未对齐长度、目标地址、入口、CRC、负载损坏共 9 类测试通过。此测试不模拟 PH1P35 QSPI 冷启动电气行为。
- 官方 `create_flash_file` 合并 bit＋两个二进制段；独立逐字节确认整个 FPGA 配置流保留、两个附加段位于正确地址、全部输入哈希一致、应用来自原 ELF。
- 合并镜像：`deliverables/camera_hdmi_v54_fpga_mcu_flash.bit`。
- 合并镜像 SHA256：`19DE3F286C5945F6D30BA901A664A52B03614E8F1704E791C32C0DF882BCA39B`。
- 生成脚本：`tools/build_v54_boot.py`、`tools/bitgen_v54_flashboot.tcl`、`tools/merge_v54_flashboot.tcl`、`tools/verify_v54_flash_artifact.py`。
- 持久烧录脚本：`tools/program_v54_flash.ps1`，严格禁止自动重复；原生日志有任何 ERROR 或缺少 program/verify 完成标记则不算成功。

## 备份与限制

原生 TD `read_flash` 在当前双 TAP 链报 `cannot get chip type of device`，未写入任何数据。改用 MCU XIP 只读备份拟放 MCU 启动程序的 128 KiB 区域：`tmp/flash_e00000_before_v54.bin`，全部 FF，SHA256 `B5A41C3758763BBEC72769FAB4A2533BF2DB0B6312D93D25A695F9E4B9E02260`。这不是全片备份。旧 v53 SRAM bit 与 v39 ELF、旧版本 deliverables 均保留。
