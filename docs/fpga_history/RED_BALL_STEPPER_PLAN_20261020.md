# 红球双轴步进跟踪：开源参考与集成规划

## 结论和本轮边界

本轮仅调研、核验现有代码与驱动手册、制定方案，没有改RTL/MCU，没有综合、烧录或启动电机。用户后续确认：两台步进组成双轴旋转云台，取消原舵机，允许FPGA+MCU协同，整机Slice上限为20000。延续先前确认的“摄像头固定、不随云台转动”；如更改摄像头安装方式，需要切换控制模型。

推荐：现有FPGA红球检测 → 板内MCU目标选择/滤波/标定/轨迹规划 → 共享硬件双轴STEP脉冲发生器 → DCC-100v3。借鉴运动控制内核，不把PC OpenCV或完整CNC固件塞入现有MCU。

用户最新补充已购买独立12V/2A电源，替代此前开发板5V经MT3608升压供电。12V在驱动板11–26V范围内。电源额定输出24W，但这不等于已验证两电机同时运行安全或可靠；仍须核对电机额定相电流、驱动限流及实测电压/温升。步进相电流不能简单相加后直接与电源2A比较。

## 当前工程可复用部分

- `rtl/user/ua_track_detect.v`：现有红色目标候选、形状判断、平滑边框及中心。当前中心是包围盒中心，不是面积矩质心。
- `rtl/user/ua_red_ball_uart.v`：筛选红圆目标、3帧取得目标，可靠捆绑数据CDC，传入板内UART1。产品视频1280×720映射为320×180，不能照旧独立例程的320×240使用。已有过期序列处理，规划中新旧协议需统一时间戳/序号语义。
- `mcu_tracking/camera_app/tracking_control.h`：现有固定摄像头的绝对坐标→舵机PWM映射，不是累加PID；其默认比例未经物理标定。改步进后要输出绝对步数，不是照搬1300–1700us。
- `mcu_tracking/aruco_firmware/main.c`：当前MCU v55还运行ArUco，控制必须非阻塞、计时有界，不能每次目标更新都执行一段阻塞旋转。
- `addons/stepper/`：已有有限往返扫描RTL、寄存器及MCU原型和仿真，不是已部署步进功能。当前20–200pps、有限扫描，尚无持续目标位置更新/加减速/回零，需升级，不直接当跟踪控制器。

## 关键控制模型：固定摄像头

摄像头固定时，电机转动不会使球在图像中回到中心。不能把像素中心误差一直积分成运动，否则可能持续撞限位。

第一版建议限定球在一个已知距离的平面内运动，标定9–25组“图像位置→电机步数”，先做仿射/分段查表，必要时平面单应性+机构几何映射。标定必须包括轴交换、方向、零位、比例、两轴耦合及镜像。得到 `target_steps_x/y` 后与已发脉冲的命令位置比较，控制电机到绝对目标。

如果球在任意深度移动，单张二维坐标不足以唯一确定三维位置。摄像头与转台存在基线时，固定距离的映射会有视差；需深度信息、已知球直径+相机标定的近似测距或限制工作平面，不能承诺一个二维线性比例覆盖所有距离。

若以后摄像头安装到云台上，则改为图像中心误差→目标角速度的视觉伺服；此时才适合死区+P/PD+速度前馈。两个模式不混用。

## 算法链和运动行为

1. 复用红色连通候选+圆形约束，叠加面积范围、长宽比和与上一目标的距离，避免大块红背景抢目标。首版不增加Hough圆检测。
2. 使用最新目标，过滤异常跳点；现有FPGA已有平滑和取得确认，不再叠加多层强低通。必要时在MCU加轻量alpha-beta位置/速度预测，先测实际延迟再设置预测时间。
3. 将有效坐标映射为绝对步数。第一版不启用积分，优先完成静态定位与坐标标定。
4. MCU产生受速度/加速度限制的短轨迹段；目标变化时平滑重规划，避免“走完旧目标再处理新目标”和长队列积累延迟。先梯形加减速，确有机械共振再做S曲线。
5. 硬件独立输出STEP高低电平、DIR建立/保持、计步和超时保护。MCU只更新参数，不在ArUco主循环里忙等发脉冲。
6. 起步调度目标：视觉约50Hz现有链路，MCU轨迹100–200Hz作为待测目标；硬件脉冲独立运行。须测MCU最差服务间隔及ArUco同时运行情况，不能把主循环平均速度当实时保证。
7. 正常丢球时减速停、保持当前位置；长时间失联进入故障策略。俯仰轴停机是否断电需看自锁/制动/重力负载，不能一律休眠让机构下坠。硬急停、硬限位独立优先。

步数是命令位置，不是编码器实际位置。需要回零开关恢复绝对参考；上电不能把“软件计数=0”当物理回零。第一阶段低速小角度测试，目标取得不会自动解除急停或自动武装。

## 资源与MCU任务分工

当前v68最终19503/21216 Slice、97/108 ERAM、27/40 DSP。用户明确将原92%门槛替换为整机20000 Slice，现有基线下预算497 Slice；不是新增模块可用2000 Slice。芯片物理余量1713 Slice不能当作20000目标内的可用余量。

优先MCU做标定、预测、加减速等低频运算，FPGA复用视觉和总线，提供共享双轴STEP时基/小寄存器。原舵机明确取消，因此可以移除舵机专用50Hz PWM、1300–1700us映射、旧舵机控制命令和后备GPIO PWM路由，保留共享SysTimer/串口/ArUco所需部分；硬件命令位置改成步数。不可把整个MCU/ArUco外设或共享调度器当作舵机逻辑一并删除。

集成前先为脉冲引擎预留300–500 Slice的**规划预算，不是已经综合的占用估算**，回收舵机专用逻辑并共享计数/算术/寄存器译码，再测综合净增量。门槛为最终整机≤20000 Slice，ERAM≤108、DSP≤40，且最终Routed时序通过；不将“497 Slice+旧舵机估计占用”当作已测预算。若不能在仅取消舵机、保留其他功能的同时满足20000，继续优化或返回方案选择，不擅自关闭其他功能。

备选是MCU硬定时器直接出脉冲，但当前硬核封装只使用SysTimer/GPIO，是否有可用、可路由的独立比较输出尚未确认；软件逐步中断方案还需测抖动/最差负载，不能凭库能跑在Arduino上就断言适合当前硬核。

## DCC-100v3、电源和接线边界

已核对用户本地《DCC-100v3说明书-2026-05-24.pdf》第3页：PWM为步进脉冲，DIR方向，SLP高工作/低休眠，RST高工作，DCY可悬空自动衰减；控制电平3.3V，驱动电源11–26V。说明书的0.05625°/脉冲只在对应配套电机/细分配置下使用，等效6400脉冲/转；不是所有电机通用值。

例如配套配置下30°/s约533pps，90°/s约1600pps，仅为换算，不是已验证安全速度。原型200pps上限约11.25°/s，需升级后才适合更快跟踪。

12V独立电源只接驱动电源端，开发板与驱动信号共地，电机回流直接回独立电源；不向GPIO送12V，不带电插拔绕组。型号`42BL382.0-23A`尚不足以确认实际绕组类型、额定电流和限流设置，需铭牌/接线照片。先单轴空载低速，再双轴，测12V压降、电流和温升，不将电源采购视为负载验证完成。

旧文档 `STEPPER_DUAL_SCAN_20261020.md` 的E12/E16/E17/F13/F14/F18仅为历史拟用脚位，未集成；正式接线表需要重新与当前v68 ADC、板卡排针方向及用户机构核对，不能直接按旧预案上电。

## 分阶段验收

1. 机构已确认双步进旋转云台、旧舵机取消。后续核对轴限位、回零、负载、传动比、零位及两轴方向。
2. 资源原型/仿真：计步准确、正反向、DIR时序、加减速、重规划、复位OFF、通信丢失、限位和急停；MCU与ArUco并发服务时延。
3. 有限扫描：不接视觉闭环，单轴回零、小角度往返；再双轴，核验供电/电流/方向/丢步。首次必须现场人工允许动作。
4. 固定平面标定：9–25点，静态红球指向误差、重复定位误差、来回换向背隙。
5. 动态跟踪：慢移动→加速→快速换向→短遮挡→丢目标→相邻红色干扰；记录像素/步数/角度误差、延迟、丢球、误跟与限位。量化指标由工作距离/视场/传动确定，不预先承诺通用毫米精度。

最终按用户流程完成综合、布线、联合Flash部署；电机仍默认OFF，下载不等于授权自动开始运动。
