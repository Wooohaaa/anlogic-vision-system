# v85：高速框、卡通描边、顶部首行修复

## 问题和边界

v83 的框坐标每帧只更新 1/4。恒速输入在理想稳态下会有约三帧的滤波滞后；这不是实测整机延迟。形状类别的两帧确认与位置平滑是两条独立逻辑。

用户录像 `2026-10-22 21-49-44.mp4` 可见高速移动时框偏离目标。自动阈值定位可能把部分框线或遮挡连通域当成完整框，故 tmp/v85_video/result.json 的拟合不能作为可靠的延迟测量，不据此声称整机只有几帧延迟。

FAST_TRACK_ENABLE=1 时，某色中心在任一方向相对已发布中心移动 ≥8 像素，该色中心与四条边作为整体直接更新到本帧测量；否则沿用原 1/4 平滑。两半共享平滑运算时锁存同一个 fast 决策，避免分别阈值导致 min/max 倒置。没有速度外推、越界预测，也不修改颜色、尺寸、面积过滤、形状防抖或掉失保持。

这只消除位置平滑的额外追赶过程，不能消除曝光、整帧检测、DDR、HDMI 或采集卡延迟。检测结果与被读 DDR 槽未做新的一一帧号绑定，仍可能存在动态叠加相位误差；真实视频上的改善必须实测，不能用零原始坐标误差仿真当作屏幕贴合保证。

## 画质修改

用户确认回退后顶部红线及卡通偏移重现，因此本版恢复已经独立验证的卡通同坐标差分；色调函数及其他 0～5 模式不变。

首行修复使用新模块 ua_top_row_repair_v85，不再使用已撤回的 ua_top_row_repair_96。在尾部每条刷新行之前提供 100 拍空白，满足生产 AWB 的固定行读取/valid 行尾重建契约。帧间至少留出 2*(WIDTH/4)+202 拍，使用约两行前视。只用已解码第二行替代首行，其余像素不改，尾两行从循环 RAM 刷新；不是重新实现 Bayer 插值，也不声称恢复首行真实独立细节。

真实 AWB 契约测试：旧 v84r1 两帧只有 4482 组/12 行，v85 与原基线均为 5120 组/16 行/0 错宽。v85 的真实 9bit AWB＋5×5 finishing＋显示算法＋96/128 打包双路径测试，逐像素、逐字、行尾、帧数和 DDR FIFO reset 提前量均需通过；1280×720 两整帧回归完成前不允许布线/烧录。

- 原始 RGB 三色移动、横向换向、纵向跳变、静态抖动、漏检及重捕获的 20 帧测试通过。受控高速阶段中心累计误差旧 598 像素、新 0；这仅相对当前帧测量值，不是 HDMI/物理目标真值。

- KEY2、MCU v83、速度与机械保护不变；部署不发送运动命令，上电默认 OFF。

## 构建迭代

v85 完整 1280×720 两帧回归通过：460800 组像素、345600 个 128bit 字，所有像素/字、720 行/帧、SOF 和 FIFO reset 提前量均与已修正的独立源参考一致。其布局 Slice 19657（92.65%），在布线之前被门限阻止，未烧录。

v85r1 只去掉共享坐标暂存六个 33bit 字的不可观察复位；所有字在 fe_d[2..7] 写入后才在 fe_d[8] 发布，对外坐标、valid 和 fast_pair 仍有复位。20 帧快速运动和带中途复位的旧行为对照再次通过。完整图像链路的全部源文件 SHA 与上述已通过回归逐项一致，单独记录 tmp/v85r1_reused_full_chain.json；没有用改动过的图像模块复用旧回归。

v85r1 最终 Routed Slice 19461/21216（91.73%），ERAM 102/108，DSP 32/40；比 v83 少 3 Slice，多 5 ERAM。SWNS=0.101 ns、HWNS=0.020 ns、STNS=0、HTNS=0，满足资源和时序门限。
