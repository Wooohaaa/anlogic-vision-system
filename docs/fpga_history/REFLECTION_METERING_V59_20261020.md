# v59：避免小面积反光压暗全画面

## 发现的问题

v57 保护逻辑可以因很少的高亮采样就降低整帧曝光。v58 增加高亮面积预算及中央亮度底线，但中央窗口中的反光依然会抬高算术均值，所以 v58 不作为最终候选烧录。

用户录像 `2026-10-20 11-05-44.mp4` 是经过 ISP/HDMI 的画面，不是传感器 RAW；从视频得到的显示域高亮比例，不可直接等同于 FPGA 线性域计数。

## 当前修复

1. 全帧固定1024点监测暖亮、热亮、近饱和区域，放宽少量孤立反光的预算。
2. 启用该模式时，中央测光每个采样最多贡献72（8位线性值）；这只限制测光反馈，不截断显示 RGB。窗口内小面积亮点不再无限抬高整幅图的曝光反馈。
3. 中央测光低于40时允许提升亮度；40至47之间对高亮采取保持；达到48后才允许大面积高亮触发降低曝光。亮度本来偏高时仍可降低曝光。
4. 保留 KEY4 开关、数码管 index00–31/启用0–1、数字暗部提升旁路，以及全部检测功能。

这是测光统计及控制策略调整，不是 HDR：单次曝光已经饱和的反光不能恢复纹理，也不能承诺强逆光下所有区域都保留细节。中央测光也不等于语义主体识别。
