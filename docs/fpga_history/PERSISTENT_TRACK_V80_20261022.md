# v80 持续开启：丢球待机、重新识别自动恢复

用户明确要求“改成一直开启不关闭”，针对v79因红球掉失超过500ms而退出的问题。v80不改FPGA、检测算法、接线、方向、限速或软限位，只修改MCU追踪状态机。

## 行为约定

- 仍须人工确认安全参考零位并发送g；上电默认OFF，不自动置零、不自动启动。
- g允许没有目标时进入mode=2的追踪待机，此时不发步进运动。
- 收到三个连续有效且新鲜的红球数据后开始追踪；有无目标都保留追踪授权。
- 目标无效或100ms没有有效数据，按原斜率减速到零，保持当前位置和驱动使能，不使用旧坐标继续转动。
- 删除“500ms丢球后st_stop”的路径。丢球一分钟、或长时间UART断流，只要主循环和硬件正常，仍为mode=2，不撤销零位。
- 再出现稳定红球，自动恢复同一参考坐标下的闭环，无需重新z/g。
- 手动s、主循环停顿超过100ms、硬件故障/250ms看门狗，仍能关闭并撤销零位；停机后目标重新出现不会自行武装。
- 每轴±160步软范围和最高120pps不变；到范围边界只停止向外运动，允许反向退出，不能把软件范围当物理限位。
- 驱动在待机时保持使能/力矩，注意电机与驱动温升和散热；“一直开启”不是允许故障后仍盲动。

## 验证

`tests/test_stepper_v80.c`增加无球启动待机、一分钟连续无效目标、一分钟完整数据断流后保持静止/授权、三帧恢复自动运动、手动停止后不自动恢复。原方向、死区、时间回绕、软限位/反向退出、扫描、变服务间隔、16组视觉延迟模型与ArUco/步进RTL共享AHB回归通过，见 `tmp/v80_stepper/result.json`。这是模型及组件证据，非连续实机追踪验收。

MCU编译text=29368、data=240、bss=16548、栈预算2048，总预算48204/49152字节。比v79少64字节代码，BSS不增加。复用已验证v77 FPGA，联合镜像FPGA数据区逐字节相同；Slice19465/21216（91.75%）、ERAM97、DSP32，原Routed时序保持。
