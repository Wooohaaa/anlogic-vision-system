# 随动摄像头红球中心闭环 v79

## 已确认的机械条件

摄像头已安装在云台上，随两只步进电机一起转动。用户实测：轴0先上/下/上，轴1先左/右，因此采用轴0正向朝上、轴1正向朝左。两轴有限扫描已实际运动；这不等同于红球闭环已经验收。

固定摄像头的像素→绝对步数仿射映射已移除，旧 M 标定命令不再使用。换成图像速度闭环，不累积像素误差，不安装虚构的相机参数。其符号基于正常非镜像成像；首次实拍闭环仍须确认误差确实缩小，不能只凭电机方向宣称视觉反馈符号已验证。

## 工作链路

FPGA 原有全画面红色圆形定位 → 原 UART1 320×180 数据包 → MCU 新鲜度/连续3帧检查 → 一阶误差滤波 → 中心死区 → P速度闭环 → 加减速/软限位 → 原 AHB 两轴 STEP/DIR 硬件。ArUco、视频、曝光、降噪、OSD 和其他检测保持不变。

- 目标中心 (160,90)。轴0误差=90-y，轴1误差=160-x；目标在上/左时对应正向，目标在下/右时对应负向。
- 新目标/失效恢复时滤波直接装入当前误差；连续帧以误差差值的1/4更新，避免起步用旧目标和明显坐标抖动。
- 每轴误差绝对值≤6像素时请求零速度；否则请求 `sign(e)*min(2*(abs(e)-6),120)` pps。无积分项、无误差累加，避免固定相机旧算法导致越追越偏。
- 名义10ms服务周期，加减速按实际经过时间约800pps/s计算，适应ArUco导致的主循环间隔变化；100ms以上主循环停顿强制关闭。FPGA仍有250ms独立看门狗和完整STEP/方向保护。
- 首版保守软范围±160步（以人工确认的安全中间位置为零），不是物理限位或已标定角度。硬件原±640步检查继续存在；不可把软限位当成机械碰撞检测。
- 硬件目标只前推一个有界制动距离，`v²/(2a)+2` 步，并夹到软范围，不把每个像素偏差累加成新绝对位置。
- 必须有3个连续有效数据包且最近有效包≤100ms，才允许手动启动。无效目标立即请求减速，100ms没有有效包也请求减速；500ms没有有效目标则关闭并撤销零位。目标重新出现不会自动武装。
- 位置仍是发出的STEP计数，不是编码器反馈；实际丢步、负载、背隙和视觉镜像尚需实测。

## 操作

上电默认OFF，不自动追踪。`?` 状态；`s` 停止；`z` 在OFF且驱动释放后确认当前安全参考零位；`x/y` 保留单轴有限测试；`n` 保留双轴有限扫描；`g` 显式请求新的随动闭环，缺零位/目标不稳定/目标过期时拒绝。首次实际测试应限时观察、随时可断驱动12V，不自动开启无限运动。

状态增加 `target,x,y,age_ms`，用于判断红球识别和数据新鲜度。相机标定并非二维居中所必需，但要获得角度/距离或更大范围一致动态响应，仍需测机械比例和相机参数。
