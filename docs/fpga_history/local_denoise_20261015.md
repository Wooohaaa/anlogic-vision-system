# 有限邻域保边降噪 v23（2026-10-15）

用户反馈 v22 在亮、暗区域均出现竖向水流状纹理，明暗交接处明显。本轮只修改降噪，不修改曝光、白平衡、黑位、色调 LUT、饱和度或 MCU 舵机控制。

## 原因与修复边界

离线复现了两种算法机制，尚不能断言实板全部条纹只由它们造成：

1. 旧算法反馈上一行已经滤波的结果。即使采用小数历史消除整数锁定，首行扰动在亮处和暗处仍可扩散到多行。
2. 旧四像素组遇输入空拍时，最后一个像素用自身代替右邻点，造成组边界平滑强度随空拍变化。

新版默认 `RECURSIVE_VERTICAL=0`：横向 [1,2,1]，纵向为当前横向结果与前两行原始横向结果的 [1,2,1]，相似颜色才参与。没有处理后结果反馈，没有跨帧平均。两组轮换行缓存和延迟第二行缓存避免同址读写依赖。宽度小于 16 时降级两行 FIR。

四像素组保留待处理字，等待真正的下一个有效字后计算右邻点；行尾直接冲刷。连续流仍为六周期，无反压，保持每周期四像素吞吐；输入有空拍时延迟可变化，valid/user/last 与数据一起传递。可选递归参数仅用于算法对照，不能作为与 v22 bit 完全一致的回退；回退应使用保留的 v22 bit。

## 离线证据

- 26 项 Python 测试通过，新增亮/暗首行纹理扩散及空拍数值不变测试。
- 8/9 位输入、4/8/12/16/1280 宽度、tone 开/关、连续/有空拍、重置脏缓存、帧首行尾、AWB/RAW 对齐测试通过。
- 首行扰动从第 4 行开始必须完全消失；1280 宽度、两帧、每配置 20480 字的 RTL 检查通过（24/63/64/128/最大码值）。
- 额外 8/9 位、16/1280 宽度的 1～11 周期不规则空拍逐字比较通过，无丢字、无额外字、无缓存碰撞。
- 手势恢复回归通过。此为模块级合成输入证据，不是新 ISP 下真实手势准确率验证。
- 合成平场输入 sigma 约 7.2，v20 约 3.16，v22 约 1.7，新版约 2.7。有限窗口比递归保留更多颗粒，换取有限空间传播；不能承诺摄像头实测具有相同降幅。

`tmp/v23_photo_regression.log` 在所有 8 位及 Python 检查通过后，因当时维护源尚未同步而在 preflight 停止；随后执行 setup/verify 通过，并单独完成 `tmp/v23_photo_wide.log` 的生产 9 位回归。暗噪声与手势日志分别为 `tmp/v23_dark_noise_tests.log`、`tmp/v23_hand_regression.log`。

首次 TD 展开发现第二行 RAM 读出寄存器同时有 RAM 时钟驱动和另一进程复位驱动；删除读出寄存器的多进程复位，使用有效历史标记屏蔽未初始化数据。随后不规则空拍 RTL 回归通过，重新完整构建。
