# 手势掉失修复记录（2026-10-14）

## 当前范围

正式工程 `contest2_hdmi_video` 的 `ua_hand_profile`，不是红球舵机追踪。产品使用 1280×720、四像素 RGB 组、隔四行采样，全画面定位后在动态窗口提取手型。ID：0 无手、1 拳头、2 单指、3 张手；本轮不新增 V 手势。

## 发现和修改

1. `isp_top_user` 原先将低光增强档位变化产生的 `background_restart_req` 同时接到手势清除端。手势已关闭运动门控、没有首帧参考依赖，因此该清除不必要。仅取消手势清除连接，运动参考 RAM 的重建逻辑保持不变。
2. 原定位器一帧无候选就撤销动态 ROI。新增两帧定位缺口容忍，保留搜索窗口位置；第三帧仍无候选则撤销。保留窗口不是强制输出手势，肤色、面积、几何和分类仍须通过。
3. 原候选确认遇到一帧分类失败就清空。新增单帧缺口桥接，允许同类候选在一帧缺口后确认；两帧缺口取消待确认结果。发布结果仍在第五个连续分类失败帧清除（60fps 时约 83ms），没有增加长时间“粘住”显示。

新增 `TEMPORAL_RECOVERY=1` 参数；仅旧 RAM 优化等价测试设置为 0，以区分存储优化等价性与本轮有意改变的时间策略。肤色阈值、手型几何阈值、图像颜色算法、红球 UART、MCU 轴向/速度均未改变。

## 尚待真实验证

用户将于采集卡到达后录制 HDMI 手势画面。本轮没有当前传感器肤色样本，没有宣称真实手势漏检已经彻底解决；弱肤色、倾斜手型、背景竞争和超大/小手仍可能失败。有限缺口容忍会降低时间过滤的严格度，因此必须同时检查无手背景误报，不能只看带手片段。

采集建议：固定机位、保留完整画面和 OSD，空场 5 秒；完整手掌依次拳头、单指、张手各 3 秒；再缓慢左右/上下移动，最后撤手 5 秒。分别录明亮、正常和暗场，保留原始录像、不裁切手指、不使用首帧作为背景模板。采集板上旧 v19 时必须标明版本；不能误以为维护源码修改已更新到板上。
