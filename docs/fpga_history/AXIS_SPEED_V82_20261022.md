# v82 整体提速、上下轴额外加强及用户命令

用户要求直接提供开关命令，并在整体提速基础上单独提高上下速度。轴0=上下、正向向上；轴1=左右、正向向左，均沿用用户实测。改动前读取v81并发s，确认mode=0、status=0；没有运行中改速度。

## 最终采用参数

| 项目 | v81 | v82 上下轴0 | v82 左右轴1 |
|---|---|---|---|
| 最高请求速度 | 300pps | 450pps | 400pps |
| 加减速 | 1600pps/s | 2800pps/s | 2000pps/s |
| 中心外基础增益 | 3 | 3 | 3 |
| 大偏差附加增益 | 无 | 超出18像素部分额外×3 | 超出18像素部分额外×1 |

这里“偏差”指减去6像素死区之后的误差绝对值。基础速度为 `3*excess`，当excess>18时叠加不同轴的大偏差增益，最后夹到各轴上限。上下在大偏差时额外增强；中心附近保留温和控制，不能理解成所有时候都以最大速度转动。

100Hz名义服务周期、实际dt斜率补偿、1/2坐标滤波、±640步范围、丢球减速待机、稳定三帧自动恢复、人工停止、故障和看门狗保护保留。制动前推距离用各轴自己的加速度计算，不共用旧制动参数。单轴/双轴测试速度不变，本轮只修改追踪。

## 被撤下的候选

初始左右450/上下600pps，上下3200/左右2400pps/s，上下近中心增益4、大误差增益更强。首轮16组小偏差模型通过，但大偏差、2像素/步、150ms观测延迟时出现过冲，模型目标y=-4离开视场，未编译部署该候选。按失败收敛到上表参数后，16组与12组大偏差模型均通过。未为了保留更高名义速度而忽略失败。

## 用户命令

串口COM15、115200/8N1、不发送换行：g开启持续追踪/待机，s关闭，?状态。重启或s关闭后零位被撤销，需在OFF且确认云台位于安全参考位置时先z置零再g。不能靠软件假定物理已回零。

新增 `../mcu_tracking/motor.ps1`，用户可在PowerShell进入该目录后运行：

```powershell
.\motor.ps1 on -ConfirmZero
.\motor.ps1 off
.\motor.ps1 status
```

三行是独立动作，不是要求一次全部执行。-ConfirmZero是操作者明确确认当前位置可作为安全零位，不应在不安全姿态下使用。已开启时on不重新置零。无该开关且没有有效零位时拒绝启动；上电默认OFF，不自动运动。工具开启前核验v82/硬件状态，失败时尝试停止；关闭会等待尾部释放后确认。status已在当前v81板上验证读取正常；新v82的真实开启/运动待冷启动验证。

## 验证与资源

- 控制器回归覆盖两轴各自速度/斜率、峰值上下450/左右400、扫描/方向/死区、丢球与断流一分钟保持待机、三帧恢复、停止不自动复启、±640两端和反向退出、故障、32位时间回绕、10/30ms服务间隔。
- 16组理想视觉模型，以及12组大偏差/延迟模型通过。与冻结SHA核验的v81控制器对照，大偏差稳定时间合计15150→14280ms（平均约缩短5.7%）。其中2像素/步、150ms延迟仍更慢（1580→1870ms），未声称所有场景都更快。模型不是实机电机/检测精度或丢步证明。
- 原FPGA共用AHB新增核验±640目标与上下+450/左右-400pps提交和读回；步进RTL、旧AHB、ArUco运行回归通过，见 `tmp/v82_stepper/result.json`。
- MCU交叉编译text=29508、data=240、bss=16548、栈预算2048，总预算48344/49152字节；BSS未增加，未测运行栈高水位。
- FPGA完全复用已验证v77，未重新综合/布线，联合镜像FPGA数据区逐字节相同。Slice19465/21216（91.75%）、ERAM97、DSP32，SWNS+0.009ns、HWNS+0.020ns保持。

联合Flash已通过一次官方BitWriter写入与Page program and verify，耗时约102秒，最终标记 `V82_FLASH_PROGRAM_VERIFY_COMPLETE`，记录 `tmp/v82_flash_programmed.json`、`tmp/v82_flash_program.log`。状态为 `FLASH_PROGRAMMED_NATIVE_VERIFY_PASS_COLD_BOOT_PENDING`。镜像 `deliverables/camera_hdmi_v82_fpga_mcu_flash.bit` SHA256 `65BC02056EE7B70EF0636A469EE24F9A1FC6A55176AE3B96257AE0C125E27222`；MCU ELF SHA256 `A86B16F0F70103C6263CB787CA630AEF85FED74D8A6F70F269B38000C35F84D3`。
